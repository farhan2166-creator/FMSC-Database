# Communication Center

This optional module sends external parent/guardian and staff messages. It is not an internal notification bell. The application continues to require the approved schema-6 database. Opening the page does not install database objects, start a dispatcher or enable live delivery.

## Deployment gate

1. Review `Migrations/Communication/001_CommunicationCenter.sql` and this guide. Back up the intended database and restore a disposable copy. Confirm the existing application compatibility verifier passes first.
2. Test the add-on on that copy. Execute the whole script in **one SQL connection**, with `XACT_ABORT` retained, after setting `EXEC sys.sp_set_session_context @key=N'FMSC_CommunicationInstall',@value=1;`. Stop on the first error and roll back/close that connection; do not continue individual failed batches. The script refuses an existing `comm` schema and does not overwrite an earlier installation.
3. It creates only the additive `comm` module, its restricted webhook principal, and seven optional application permission definitions. It does not change financial procedures, base version 6, existing role grants or the approved DACPAC. No installation/startup workflow executes it automatically. The installer still discovers only top-level numbered migrations; the nested add-on is intentionally outside that chain.
4. Administrator retains full authority. Explicitly grant the needed permissions to other operators through Users & Roles. Accountant receives **no new grants**. Grant Compose with View, Students.View for student/family recipients, Staff.View for staff and Fees.View for financial messages. Sending bulk requires Send and Bulk; approval requires Approve; contact/template/gateway/rule administration requires Configure. History permits viewing other operators' messages. SQL procedures enforce these checks as well as the UI.
5. Test normal school operations and backups on the disposable copy. Before production use, the owner must approve deployment, repeat verification on the intended installation, and follow the existing DACPAC refresh process for a deliberately changed schema. Material changes require review; never use metadata-only hash synchronization to approve this add-on.

The add-on has its own version and exact stored-module definition checks plus essential column/index/trusted-constraint checks. An altered procedure disables the page. This is additional validation, not a replacement for the reviewed base DACPAC contract. Do not remove the schema from a database that contains communication history as a routine rollback. Stop dispatch, disable the module and retain/restore an approved backup under the normal recovery procedure.

## First use without provider accounts

Start in **Disabled** mode (the default, with master pause on). Review a stock English or Urdu template and create an approved version. Add a contact from Students, Families or Staff, or enter a manual contact. Consent administration requires Configure; staff recipient searches require Staff.View and balances appear only in the permission-checked outstanding filter. A candidate telephone number is not proof that a guardian controls it: verify ownership and record channel/purpose consent and its source. Phone entry accepts Pakistani mobile `03…`, `92…`, `+92…` and `0092…`; ambiguous local/incomplete numbers and Pakistani landlines are refused. Other countries need a full international number.

Use **Simulation** with suitable limits and explicit unpause to exercise the workflow without external requests. Select recipients, preview exclusions and rendered messages, then Create Draft. In Outbox, confirm Submit, obtain approval where required, and explicitly Start Dispatcher. Simulation results say `SIMULATED_NO_NETWORK`; they do not establish delivery. CI additionally blocks creation of live providers through the OS credential store.

Changing a phone clears UI verification/consent checkboxes. A new number or renewed opt-in requires fresh recorded evidence. Concurrent edits use a row-version check so a stale editor cannot reverse a newer opt-out. Past message destinations remain immutable. Financial templates require a particular student's contact; family/manual templates cannot contain student financial or academic placeholders. Family-level campaigns deduplicate shared destinations; student-specific financial messages retain separate student identity.

## Normal operator flow

- Compose / Bulk offers campus, academic year, class, section, family, staff, manual, pending-student and outstanding-balance filters. Search results are bounded to 100 rows per page; selections persist across pages, with a configured campaign maximum (hard ceiling 500).
- Preview explains missing verification, consent, scope, language, provider mapping or current financial eligibility. Available estimates use configured provider prices; unknown prices block live dispatch. SMS segments distinguish GSM-7 extension characters from UTF-16/Urdu text.
- Drafts are immutable snapshots. New Message starts another draft. Outbox supports search by student, contact, campaign ID/error code and state, details, scheduled work, submission, approval, pause, cancellation and constrained retry. Preview and final campaign confirmation show recipient count, channel, mode and available cost.
- Approval is required at the configured recipient threshold and for rules configured to require it. An operator cannot approve their own campaign; Administrator can, supporting a single-owner installation. An explicitly approved rule may authorize its future campaigns, but limits and consent still apply.
- Accepted means only that a provider returned a valid reference. Sent, Delivered and Read require subsequent provider evidence. Twilio status is checked with the administrator's Check Provider Status action. Meta status requires the optional signed webhook receiver. Unsupported or uncertain submissions require provider-console investigation, not another Send click.
- Revoke Selected disables a template version for unsent work, retaining history. Pause/cancel affect only work not already submitted; external delivery cannot be recalled.

## Reliability and cost controls

SQL claims, unique request/event/provider identities and leases protect concurrent operators and process restarts. A timed-out, interrupted or expired submission becomes DeliveryUnknown and is never blindly replayed. Explicit 429 refusal uses the provider Retry-After with bounded retries (maximum three attempts); other errors have structured, sanitized codes. A successful business transaction is never rolled back because messaging fails.

Master pause, quiet hours (configured fixed UTC offset), per-campaign maximum, hourly/daily attempt caps, recipient approval threshold and daily/monthly estimated budgets apply centrally. Estimates reserve each attempted submission conservatively; they are **not a provider billing guarantee**. Configure prices in one currency and review provider invoices. Balance/account-health API display is not implemented. Rate is deliberately capped at one SQL claim per second and the supplied dispatcher polls every five seconds, keeping resource use low; this is bounded school messaging, not a high-throughput marketing engine.

Rules default disabled. Explicit activation establishes a future-event boundary for completed admissions, verified payments, promotions and returns. Monthly outstanding rules evaluate current balances. Rules inspect committed production records without triggers or changes to business writers. Repeated evaluation uses unique event/contact identities. Before submission the queue rechecks contact consent, destination, template approval and current financial state; a paid or changed-balance reminder is suppressed for fresh review. A receipt uses its actual payment enrollment, not a later academic placement.

## SMS: Twilio setup

The implemented adapter uses the official authenticated Messages REST API at `api.twilio.com`, supports Unicode and records message SIDs. Twilio documents Pakistan coverage, but this is **not proof of your sender or campaign approval**. Before live use, obtain an account, confirm Pakistan destination availability, permitted traffic, sender registration/identity behavior, local DND/opt-out obligations and costs with Twilio and applicable Pakistani authorities. Sender IDs may be changed by networks; do not promise preserved branding. This project has not completed a legal/commercial telecom approval review.

Configure the Account SID, new auth secret and authorized sender under Secure Gateway Credentials. Secrets are encrypted using Windows DPAPI CurrentUser and stored outside the repository under the Windows user's LocalAppData/FMSC_SMS/Communication folder. They are never read back into the UI. Restrict access to that Windows profile. Configure SMS unit price, caps, consent, registration confirmation and Live mode separately. A Twilio trial/test account is not permission to message real families. Use only provider-verified synthetic/test destinations for opt-in external acceptance; there is no live CI delivery.

Official references: [Pakistan guidance](https://www.twilio.com/en-us/guidelines/pk/sms), [Messages resource](https://www.twilio.com/docs/messaging/api/message-resource), [message status](https://www.twilio.com/docs/messaging/guides/outbound-message-status-in-status-callbacks).

Twilio receipts are polled on demand. Inbound SMS STOP/webhook processing and a background SMS reconciliation service are not supplied in this phase. Where the selected sender cannot receive replies, provide a real opt-out contact route and record manual opt-outs promptly. Do not launch campaigns without that operational process.

## WhatsApp: official Meta Cloud API setup

Obtain a WhatsApp Business account, approved business phone number and appropriately scoped access token through Meta; choose a currently supported Graph API version. Add an approved provider template name, exact language code and ordered body placeholders to each reviewed local template. Local review does not grant Meta approval. The adapter sends **template messages only** through `graph.facebook.com`, avoiding unsupported free-form messages outside the customer-service window. Utility/financial/announcement classification locally is not Meta category approval; Meta controls the actual template category and eligibility.

Configure phone-number ID, token and Graph version in the secure editor. Trial destinations must be explicitly registered in the provider's test environment. Provider account creation, template approval, sender eligibility and actual delivery have **not** been performed by this implementation. Media/document templates and general inbound conversation UI are deferred until an approved secure media/reply workflow exists. No WhatsApp Web, personal-account automation or QR scraping is used.

Official references: [Cloud API](https://developers.facebook.com/docs/whatsapp/cloud-api/), [messages](https://developers.facebook.com/docs/whatsapp/cloud-api/reference/messages), [webhooks](https://developers.facebook.com/docs/whatsapp/cloud-api/webhooks/).

## Optional runtime components

`CommunicationWorker` is an opt-in .NET 8 Windows console dispatcher. Publish separately; it is not installed/started by the application installer. Run it as the Windows user who owns the supported LocalDB instance and DPAPI gateway secrets, or configure a supported explicitly reachable SQL Server. It refuses database attachment. Set `FMSC_COMM_WORKER_ENABLED=yes`, `FMSC_COMMUNICATION_CONNECTION` (existing catalog, no AttachDBFilename), and `FMSC_COMMUNICATION_ACTOR` (dedicated authorized application user). Set `FMSC_COMM_EVALUATE_RULES=yes` only for an actor allowed to configure, send and approve rules. The process exits on unrecoverable SQL errors. Use a properly configured supervised Windows scheduled task/service host for unattended operation; no service hosting has been provisioned here. Never run both it and an unsupervised desktop loop assuming duplicate work is harmless; SQL claims protect overlap, but operator ownership determines which campaigns each dispatcher may process.

`CommunicationHost` is a separate .NET 8 ASP.NET Core Meta receipt/opt-out gateway, **not a hosted service supplied by this repository**. Publish behind a trusted HTTPS reverse proxy or configure Kestrel HTTPS; keep its origin private, impose network limits and never expose SQL to the internet. Maximum request body is 64 KiB, concurrent requests are bounded, and payloads are neither logged nor retained. Configure secret environment values `FMSC_META_APP_SECRET`, `FMSC_META_VERIFY_TOKEN`, plus `FMSC_META_BUSINESS_ACCOUNT`, `FMSC_META_PHONE_ID`, `FMSC_COMMUNICATION_CONNECTION` and `FMSC_COMMUNICATION_ACTOR`. Do not use command-line arguments or commit a populated environment file. Protect secrets through the host's secret manager. Configure GET/POST `/whatsapp` in Meta and subscribe to message status/replies.

The receiver verifies the exact-byte HMAC, business account, phone-number ID, bounded timestamps and event count before SQL. SQL deduplicates payload hashes and prevents state regression. A signed receipt arriving before the send acknowledgement is held by provider reference and reconciled when that acknowledgement is recorded; unmatched references expire after seven days. Signed text STOP/UNSUBSCRIBE/بند opts out matching contacts; old callbacks cannot override newer consent evidence. It does not create a conversational inbox. Duplicate signatures are not permission to send another message.

For a server deployment, create a dedicated SQL login/user and add **only** that database user to `FMSC_CommunicationWebhook`; do not grant db_owner or table-write access. The script grants the role execution of `comm.IngestMeta`, communication module metadata visibility and its version marker only. The configured application actor must independently retain Communication.Send. For same-user LocalDB testing only, the gateway impersonates the script-created no-login ingress principal and always reverts it. The web host checks the add-on contract; administrators must validate the full base compatibility before deployment. Desktop and worker retain the existing full base validator.

No public endpoint, TLS certificate, always-on host, external callback subscription or unattended Windows task has been provisioned or verified. Database backups now also contain message bodies, destinations, contact consent and audit history: protect them like school records. Establish a retention policy and secure administrative deletion/archive process before long-term live operation; automatic retention deletion is not implemented.

## Tests and extension

```powershell
dotnet run --project Tests/CommunicationChecks/CommunicationChecks.csproj -c Release
dotnet build CommunicationWorker/CommunicationWorker.csproj -c Release
dotnet build CommunicationHost/CommunicationHost.csproj -c Release
python Tests/LifecycleSqlChecks/run.py --communication-only --output <private-temp-evidence> --state <private-temp-owner-state>
```

The focused SQL command provisions the existing guarded, uniquely named, loopback-only disposable SQL Server 2022 environment using the approved **schema-only** test DACPAC. It applies the add-on only there, invokes real production admission/payment writers and messaging services, and destroys the container. Omit `--communication-only` to run the full lifecycle and existing Quick Registration/mutation/administration suites too. No school database, live gateway or real network failure is required. Sanitized report/summary artifacts contain scenario names and assertions, not phone/message/credential payloads. Native Windows checks cover page construction, permission navigation, drafts, scrolling, themes and disposal without SQL. Visual DPI/interactive operation, real provider delivery and hosting acceptance remain separate.

Additional channels implement `IMessageProvider` and must pass through the same SQL consent, approval, queue, budget and history boundaries. Do not place HTTP requests in form handlers or add financial-trigger side effects. Schema/module edits require a reviewed additive deployment plan and matching contract tests, never an edited production DACPAC hash to silence checks.
